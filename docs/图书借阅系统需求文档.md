# 图书借阅系统需求文档

版本：v0.1（需求草案）  
编写日期：2026-09-30  
项目定位：面向小型图书室的图书借阅管理工具，同时作为关系型数据库学习项目。

## 1. 项目背景与目标

小型图书室使用表格或纸质记录管理借阅时，容易出现馆藏数量不清、同一本书重复借出、归还记录遗漏、逾期难以追踪等问题。本系统提供图书建档、馆藏管理、读者管理、借书、还书、续借和查询统计功能。

第一版需要完成业务流程：**管理员录入图书和馆藏 → 创建读者账号 → 读者查找图书 → 管理员办理借阅 → 查询到期情况 → 续借或归还 → 更新馆藏状态与借阅记录**。

学习目标：

- 区分实体与实体关系，设计主键、外键、必填和唯一约束。
- 编写增删改查、多表关联、分组统计和分页查询。
- 使用事务维护借阅记录与馆藏状态的一致性。
- 理解同时借书、重复提交时的并发问题。
- 使用索引和查询执行计划优化检索，并练习数据库迁移、备份和恢复。

## 3. 核心概念

### 3.1 图书与馆藏副本

“图书”是一个具体版本的书目信息，例如某出版社某一版的《数据库系统概论》。“馆藏副本”是实际摆在图书室里的一册实物。

同一种图书可以有多册副本，每册都有唯一的馆藏编号。**借阅记录关联具体副本，不能只关联书名或修改一个库存数字。** 不同版本原则上分别建档。

示例：

| 图书 | 馆藏编号 | 状态 |
| --- | --- | --- |
| 数据库系统概论（某一版本） | LIB000001 | 可借 |
| 数据库系统概论（某一版本） | LIB000002 | 已借出 |
| 数据库系统概论（某一版本） | LIB000003 | 不可借 |

该图书当前有 3 册未注销馆藏，其中 1 册可借。可借数量根据副本状态计算。

### 3.2 逾期

逾期是根据“应还日期”和归还情况计算的结果，不单独作为需要人工更新的借阅状态。

- 未归还：当前本地日期晚于应还日期时逾期。
- 已归还：实际归还的本地日期晚于最终应还日期时，记录为逾期归还。
- 应还日期当天归还不算逾期。
- 逾期天数为当前日期或归还日期与应还日期的日期差。

## 6. 功能详细要求

### F01：账号与登录

- 使用用户名和密码登录，成功后根据角色进入对应页面。
- 密码设置、初始化和重置统一要求 5～128 个字符，不能全为空白；此规则更新于 2026-10-12。
- 登录错误使用统一提示，不暴露账号是否存在；连续失败请求需要限速。
- 新建或重置的读者账号首次登录必须修改初始密码，在修改前不能访问业务功能。
- 修改密码需要验证原密码；修改成功、密码重置或账号停用后，已有会话失效。
- 退出后原会话失效；会话过期时提示重新登录。
- 密码不在列表、日志或数据库中以明文保存。初始密码只在创建或重置当次提供给管理员，不支持以后查询原密码。
- 第一版没有邮箱找回密码，读者联系管理员重置；部署说明提供初始管理员的密码重置方法。

### F02：图书管理

- 管理员可以创建和编辑图书：书名、作者、出版社、ISBN、出版年份、版本说明、分类及简介。
- 书名必填，1～200 个字符；作者必填，1～200 个字符，可用文本记录多个作者；出版社和版本说明可为空，各最多 200 个字符；简介最多 2,000 个字符。
- ISBN 可为空；有值时去掉空格和连字符，校验 ISBN-10 或 ISBN-13 的格式及校验位，将 ISBN-10 转为对应 ISBN-13 后判重，避免同一版本重复建档。无 ISBN 图书允许人工录入，不按书名强制判重。
- 分类必选；出版年份可为空，有值时为 1～9999 的整数。
- 图书详情展示书目信息、未注销馆藏总量、可借数量；管理员可进一步查看每册副本及历史记录。
- 支持关键词检索书名、作者、出版社和 ISBN，英文大小写不区分，并支持分类筛选。
- 不硬删除图书。归档前检查无未归还借阅；归档后从读者普通列表隐藏，禁止新增借阅，但管理员仍可查询历史。
- 支持恢复归档图书；恢复不自动修改副本状态。
- 第一版封面使用占位图，不依赖外部图片或封面上传。

### F03：分类管理

- 使用单层分类，例如“计算机”“文学”“历史”，不实现分类树。
- 名称去除首尾空白后为 1～30 个字符，英文大小写不区分，同名分类不能重复创建。
- 管理员可以创建、改名、删除分类。
- 分类下仍有图书时不能删除，包括已归档图书；需先调整图书分类。

### F04：馆藏副本管理

- 管理员在已有图书下添加副本，馆藏编号全局唯一，系统生成，不使用 ISBN 替代馆藏编号。
- 记录所属图书、馆藏编号、位置、状态、备注和建档时间；位置最多 100 个字符，备注最多 500 个字符。
- 初始状态为“可借”；同一本书的多册副本使用不同编号。
- 状态包括“可借”“已借出”“不可借”“已注销”。不可借用于破损、盘点等暂时不能流通的情况，需记录原因。
- 可借与不可借可由管理员切换；可借副本办理借阅后变为已借出；已借出副本正常归还后变为可借，破损归还时变为不可借。
- 已借出副本不能直接设为可借、不可借或已注销，必须通过归还流程处理，避免绕过借阅记录。
- 没有未归还借阅的副本可注销，需确认并记录原因；已注销副本不再流通，不硬删除，保留历史。
- 第一版不提供已注销副本恢复入口，注销属于需要明确提示的操作。
- 已有借阅历史的副本不能改为另一种图书，也不能更换馆藏编号。

### F05：读者管理

- 管理员创建读者账号与资料，包含用户名、姓名、读者编号、可选联系电话、账号状态和备注。
- 用户名为 3～32 位字母、数字或下划线，英文大小写不区分，全局唯一；姓名必填，1～50 个字符。
- 读者编号系统生成且唯一；联系电话最多 30 个字符，备注最多 500 个字符，不要求收集身份证号。
- 账号初始为启用状态。管理员可以编辑资料、停用、恢复和重置密码。
- 停用账号不能登录、新借或续借，但既有借阅记录保留，管理员仍可办理归还。
- 读者不硬删除，读者编号不重复利用，避免历史记录失去归属。
- 读者详情展示当前未还数量、逾期情况和借阅历史。

### F06：办理借阅

- 管理员通过读者编号或姓名查找读者，再输入馆藏编号定位实物副本；姓名重名时用读者编号确认。
- 办理前检查：读者启用、当前未还数量小于 5、没有逾期未还记录、图书未归档、副本可借。
- 每次办理一册，一次借阅生成一条记录。借阅日期由服务器当前时间确定，不允许页面任意回填。
- 应还日期为借阅本地日期加 30 天。例如 2026-09-30 借出，应还日期为 2026-10-30，可在当天归还。
- 成功后保存读者、副本、借出时间、应还日期、经办管理员和借阅规则快照，并将副本标记为已借出。
- 借阅记录创建与副本状态更新必须在同一事务中完成；失败时不产生部分成功结果。
- 两人同时借同一册时，只能有一个请求成功；两次同时借阅也不能突破同一读者的借阅上限。
- 重复点击或网络重试不能生成重复借阅。提交失败保留已选读者和副本，显示失败原因。

### F07：办理归还

- 管理员输入馆藏编号，查出唯一的未归还记录，确认读者与图书后办理。
- 记录归还时间、经办管理员、归还备注，以及实物是否可继续借出。
- 正常归还将副本设为可借；破损归还设为不可借并要求填写原因。
- 归还时展示是否逾期及逾期天数，不收取或计算罚款。
- 借阅记录与副本状态在同一事务中更新，完成后读者未还数量同步减少。
- 没有未归还记录时提示“当前无待归还记录”，不新建归还记录；重复提交不能重复改变借阅状态。
- 禁止未收到实物就用归还操作处理遗失。遗失与赔偿流程列为后续功能，第一版可在借阅备注中记录情况，仍保持未归还状态。

### F08：续借

- 启用的读者可以为自己的未归还借阅申请续借，管理员可代办，二者遵循相同规则。
- 当前借阅尚未逾期、尚未续借，且读者没有其他逾期未还记录时可以续借；应还日期当天仍可续借。
- 每条借阅最多续借 1 次，新应还日期在原应还日期基础上延长 30 天，不从续借当天重新计算。
- 保存续借时间、旧应还日期、新应还日期及操作人；原始借出时间保留。
- 同时更新应还日期和续借记录，重复或并发提交最多成功一次，不能重复延长。
- 已归还、逾期或停用账号的借阅不能续借，页面显示具体原因。
- 借期、续借次数与延长天数在借出时保存快照；未来修改默认规则不追溯改变已有借阅。

### F09：借阅查询

- 管理员查询全部借阅记录；读者只能查询自己的记录。
- 展示书名、馆藏编号、借出时间、应还日期、归还时间、续借情况及逾期天数；管理员列表额外展示读者姓名和编号。
- 支持关键词、未归还/已归还、逾期标记、借出日期范围筛选；管理员额外支持按读者筛选。
- “逾期未还”与“逾期归还”分别展示，不能将历史逾期归还计入当前逾期名单。
- “即将到期”表示未归还且应还日期在今天至今天加 3 天之间，包含两端日期。
- 默认按借出时间降序排列，每页 20 条，可切换为 50 条；同值按记录 ID 固定排序。
- 修改条件时返回第一页，显示匹配总数，空结果与请求失败分别提示。

### F10：数据统计

- 管理员概览展示正常图书种数、未注销馆藏册数、可借/已借出/不可借册数、启用读者数、当前逾期未还册数。
- 未注销馆藏册数等于可借、已借出、不可借册数之和；归档图书的未注销副本仍计入馆藏，但不能办理新借阅。
- 展示最近 30 天每天的借出册数，以及该期间按借阅次数排列的热门图书前 10 名。
- 一条借阅记录计一次借阅，续借不算新的借阅；已归还记录仍计入历史借出统计。
- 热门图书可包含已归档图书，并标记归档状态；次数相同时按图书 ID 固定排序。
- 图书详情的“可借数量”按副本可借状态计算；图书已归档时，读者不可访问，管理员明确看到禁止流通提示。
- 日期范围按界面时区解释，包含完整起止日期。统计结果与明细查询保持一致。

## 8. 核心数据模型与约束

以下为概念模型，最终字段类型、索引和建表脚本在数据库设计阶段确定。

| 实体 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| 账号 users | ID、用户名及规范化值、密码哈希、角色、状态、首次改密标记、创建及更新时间 | 规范化用户名唯一；角色为管理员或读者 |
| 读者 readers | ID、账号 ID、读者编号、姓名、电话、备注 | 账号与读者资料一对一；读者编号唯一 |
| 分类 categories | ID、名称及规范化值 | 规范化名称唯一；分类与图书一对多 |
| 图书 books | ID、书名、作者、出版社、规范化 ISBN、年份、版本说明、分类 ID、简介、归档时间 | ISBN 非空时唯一；图书与副本一对多 |
| 馆藏副本 book_copies | ID、图书 ID、馆藏编号、位置、状态、状态原因、备注、建档时间 | 馆藏编号唯一；副本与历史借阅一对多 |
| 借阅 loans | ID、读者 ID、副本 ID、借出时间、原应还日期、当前应还日期、归还时间、借出及归还经办人、规则快照、备注 | 同一副本最多一条未归还记录；读者与借阅一对多 |
| 续借 loan_renewals | ID、借阅 ID、操作人 ID、操作时间、旧及新应还日期 | 第一版每条借阅最多一条续借记录 |

借阅状态根据归还时间是否为空区分“未归还”和“已归还”；逾期及当前未还数量通过查询计算，第一版不再维护独立计数字段。

数据完整性要求：

- 使用外键关联账号、读者、分类、图书、副本和借阅；不得出现失去归属的历史记录。
- 核心约束由数据库或事务保证，不能仅由页面校验。
- 同一副本最多一条未归还借阅，副本“已借出”必须与未归还记录对应。
- 初始应还日期不能早于借阅本地日期；续借只能延长；归还时间不能早于借出时间。
- 检查读者借阅上限与创建借阅应协调执行，防止两个并发请求分别通过上限检查。
- 对副本借出、归还、续借使用事务及适当并发控制，事务失败后全部回滚。
- 已产生业务记录的用户、读者、图书和副本保留，不通过级联删除清除借阅历史。
- 借出与归还经办人必须是管理员；续借操作人只能是管理员或该条借阅所属读者账号。
- 统一存储事件时间，应还日期使用日期类型；显示和逾期计算按约定时区处理。
- 借阅历史展示当前书目信息；第一版不保存书名或读者姓名的完整历史版本，编辑资料不改变记录的实体归属。

## 9. 状态与规则汇总

| 对象 | 状态变化 | 触发条件 |
| --- | --- | --- |
| 馆藏副本 | 可借 → 已借出 | 借阅成功 |
| 馆藏副本 | 已借出 → 可借 | 正常归还成功 |
| 馆藏副本 | 已借出 → 不可借 | 破损归还成功并记录原因 |
| 馆藏副本 | 可借 ↔ 不可借 | 管理员维护且没有未归还借阅 |
| 馆藏副本 | 可借/不可借 → 已注销 | 管理员确认注销，没有未归还借阅 |
| 借阅 | 未归还 → 已归还 | 管理员办理归还 |
| 图书 | 正常 ↔ 已归档 | 归档要求没有未归还借阅，恢复不修改副本状态 |
| 读者账号 | 启用 ↔ 停用 | 管理员维护；停用不阻止管理员办理归还 |

第一版不提供借阅历史删除、借出日期回填、归还撤销或已注销副本恢复。误操作更正需要后续单独设计，不能通过手工修改数据库绕过业务规则作为常规使用方法。

## 10. 非功能需求

### 10.1 性能与可用性

- 按小型图书室、1～5 个同时在线会话设计，列表使用分页。
- 在约定验证规模下，常规书目检索、读者查询、借阅列表接口响应时间 P95 目标不超过 1 秒，不计网络往返时间。
- 性能验收记录服务器配置、其他服务负载、查询条件及至少 100 次请求结果；以上是待验证目标，不代表现有服务器已经达到。
- 正常、空数据、加载中、无权限、冲突和请求失败均提供可理解的反馈。
- 借阅及归还提交结果不明时，可重新查询当前副本和借阅状态，不能直接提示用户再次办理。

### 10.2 权限与数据保护

- 权限在服务端校验，不能仅隐藏页面按钮；读者信息及借阅历史不向其他读者公开。
- 密码使用专用密码哈希算法；配置中的密码和会话密钥不进入源码、响应或日志。
- 查询使用参数化方式，登录与会话机制采取相应的请求保护措施。
- 公网实际使用提供 HTTPS，避免账号及读者资料通过未加密连接传输。
- 仅收集必要的读者信息，联系电话可选；日志避免记录完整联系电话和认证凭据。

### 10.3 部署与恢复

- 提供应用和数据库健康检查，以及可定位失败请求的错误日志。
- 使用数据库迁移脚本管理结构变化，提供启动、配置和初始化管理员说明。
- 部署前重新检查服务器资源、端口和现有服务，新项目使用独立数据库、目录和配置，不覆盖既有项目。
- 提供数据库备份与恢复步骤，第一版至少完成一次在独立测试环境中的恢复验证。
- 恢复后核对表记录数量、借阅历史、未还数量及副本状态一致性；本版本没有封面上传，暂不涉及素材文件备份。
- 后续加入自动备份时明确保存位置、周期及保留时间；这些运维参数在部署阶段确定。

## 12. 开发与数据库学习顺序

| 阶段 | 开发交付 | 学习重点 |
| --- | --- | --- |
| 1. 数据建模 | 实体关系、字段、约束、建表与示例数据 | 主键、外键、一对多、一对一、数据类型 |
| 2. 基础管理 | 登录、分类、书目、副本、读者管理 | INSERT、SELECT、UPDATE、唯一约束 |
| 3. 借还流程 | 借阅、归还、权限和业务校验 | JOIN、事务、并发控制、条件更新 |
| 4. 期限管理 | 续借、到期与逾期查询 | 日期计算、查询条件、关系一致性 |
| 5. 查询与统计 | 分页、过滤、概览和热门图书 | COUNT、GROUP BY、排序、执行计划与索引 |
| 6. 部署验证 | 独立部署、迁移、健康检查、备份恢复 | 数据库权限、迁移、备份与恢复 |

每个阶段先理解关键 SQL 的输入、输出和约束作用，再整合进接口。第一版不要求引入缓存或独立搜索服务，组件选择应由实际需求和测量结果决定。
