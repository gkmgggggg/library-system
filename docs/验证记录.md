## 登录后的自动跳转修复（2026-10-12）

- 已在浏览器复现旧行为：登录及 me 请求成功，URL 变为 `/`，但界面仍显示登录表单。原因是认证刷新调用 QueryClient.clear，移除了 AuthProvider 正在观察的 me 查询；随后 fetchQuery 的新查询没有同步该观察者。
- 登录刷新和退出清理保留 me 查询，取消旧请求，只移除其他业务查询。登录后主动 refetch 当前观察者，确认获取用户；没有建立会话时给出明确提示，避免假跳转。
- 按返回用户状态 replace 跳转：管理员 `/`、读者 `/books`、首次改密 `/change-password`。密码更新后后端已撤销会话，退出请求若为 401 视为已退出，仍完成前端状态清理和回到登录页；其他错误继续报告。
- Playwright CLI 的隔离浏览器中，以 API fixture 复现并回归前端：管理员进入工作概览、退出后以读者登录进入目录且没有管理导航、错误登录停留并报错后可重试、首次登录转改密、改密后退出为 401 仍回登录页、再次登录进入读者目录。浏览器请求均拦截为测试响应，没有使用真实账号密码或修改开发库。
- 浏览器控制台仅有测试故意返回的 me/login/logout 401，无前端运行时异常。后端真实数据库及 HTTP 认证由 `npm test` 的 33 项测试单独验证，使用临时 PostgreSQL，全部通过；类型检查、前后端构建及 diff 检查通过。
