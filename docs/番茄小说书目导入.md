# 番茄小说公开书目导入

日期：2026-10-12。目标是在本机 `library_dev` 添加约 1000 本真实网络小说书目，用于分类、搜索、分页和统计练习。

**本次实际结果：已导入 322 本，目标 1000 本尚未完成。** 采集途中书目页开始返回 HTTP 200、Content-Length 0 的空响应；等待数分钟后复查此前正常的书目页仍为空，因此停止进一步采集。有效缓存、导入工具及去重记录均已保留；网站恢复公开访问后可重新执行采集与导入命令，已有来源 ID 会跳过。没有用虚构书目填补缺少的数量。

## 采集范围

- 来源为 [番茄小说公开书库](https://fanqienovel.com/library) 和每本书的 `https://fanqienovel.com/page/书目ID` 页面。
- 先检查官方 `robots.txt`，再读取书库默认排序的分页；仅用目录中的 ID 访问公开书目页。不需要登录、Cookie 或签名算法。
- 全部请求共用限速，默认每两秒最多发起一个请求，最多两条在途请求。401、403、429、空响应或验证跳转时停止，不绕过访问限制；网络超时及服务器异常最多重试两次。此次曾按每秒一次采集，出现空响应后停止，后续使用更保守的默认速率；是否恢复公开访问由网站决定。
- API 文字使用网页字体编码，因此只从 API 获取 ID，书名、作者和分类取自书目页的可读数据，不解码字体。
- 保存书名、作者、主分类、题材标签、连载状态、来源地址和采集时间。简介字段是根据题材、状态、字数生成的信息概览，并附原书目链接；没有复制故事简介、章节正文或下载封面。
- 这是一批当前目录样本，不代表全站完整目录，也不承诺平台当前阅读数或内容质量。分类和连载状态是采集时的快照。

## 执行

在项目根目录运行：

```bash
npm run catalog:crawl
bash scripts/backup.sh
npm run catalog:import
```

`catalog:crawl` 仅采集，不连接数据库。结果在 `data/fanqie-catalog.json`，每页原子保存，可再次运行继续；达到 1000 本后再次运行直接复用缓存。需要新一轮采集时使用另一个输出路径，例如：

```bash
python3 scripts/crawl-fanqie.py --limit 1000 --output data/fanqie-next.json
npm run catalog:import -- data/fanqie-next.json
```

`catalog:import` 构建 Java CLI，沿用应用的数据库连接配置，在非 Web 模式下先执行 Flyway 迁移，再导入 JSON。默认目标仅为本机 127.0.0.1:55432 的 `library_dev`；不要设置到其他业务库。采集和导入不启动或停止正在运行的前后端服务。

## 数据规则

- 使用 V2 迁移新增 `book_sources` 与 `catalog_import_batches`，V1 不修改。
- 所有输入先校验：单批 1～1000 条、来源 ID 唯一、链接和 ID 对应、字段不超数据库长度、无字体编码乱码。
- Java Service 使用参数化 SQL 和一个事务完成分类、书目、来源及批次写入。数据库错误整批回滚；同一来源的并发导入通过事务锁串行化。
- `book_sources(source, external_id)` 唯一。再次导入同一书目跳过，不覆盖管理员手动编辑或归档状态。
- 不猜测 ISBN、出版社、出版年和版次，保持 NULL。新增书目的馆藏副本为 0，不能借阅。只有实际购入实体版本并核实资料后，管理员才应登记实物副本。
- 每次成功导入输出批次 UUID、新增和跳过数量；来源记录关联首次创建它的批次。全部重复的批次会记录 0 新增，不改变现有书目。

## 检查和回退

```sql
SELECT source, count(*) FROM book_sources GROUP BY source;
SELECT b.title, b.author, c.name, s.source_url, s.fetched_at
FROM books b JOIN categories c ON c.id=b.category_id
JOIN book_sources s ON s.book_id=b.id LIMIT 20;
SELECT id, input_count, inserted_count, skipped_count, created_at
FROM catalog_import_batches ORDER BY created_at DESC;
```

备份默认保存到工作区外 `~/Library/Application Support/library-system/backups`，权限受限，不能提交 Git。需要撤回本次样本时，优先按批次归档书目，而非删除数据库或覆盖整个开发库。下面的 SQL 先以真实批次 UUID 替换参数，并核对数量；只归档没有副本的书目，保留来源和审计，避免影响后来登记的实体馆藏。

```sql
BEGIN;
UPDATE books b SET archived_at=now()
FROM book_sources s
WHERE b.id=s.book_id AND s.import_batch_id='本次批次UUID'::uuid
  AND b.archived_at IS NULL
  AND NOT EXISTS (SELECT 1 FROM book_copies bc WHERE bc.book_id=b.id);
-- 核对 UPDATE 数量后 COMMIT；不符合预期时 ROLLBACK。
```

归档后可以用现有管理页面逐本恢复；已创建副本的书目应通过既有业务流程检查和归档。本操作说明没有自动执行回退。本次首次导入批次为 `9b576732-124c-40dd-bc5c-bf762187d793`，新增 322 本。

最终核对：数据库现有 322 本书、322 册可借学习副本、32 个分类和 322 个本地封面关联；每本恰好一册副本，演示书为 0，账号仍为 1、借阅仍为 0。封面文件共 21,809,913 字节（约 20.8 MiB），全部 322 张通过 Java ImageIO 完整解码和清单 SHA-256 校验。再次运行封面命令复用全部有效缓存，不重复请求网站。前后端本地服务已更新，刷新图书目录可查看封面。

维护入口：

```bash
bash scripts/backup.sh
npm run catalog:prepare
npm run catalog:covers
npm run catalog:covers:import
```

- `catalog:prepare` 是显式的数据清理及补充命令，普通启动不会自动执行。它只匹配四本初始虚构书目的完整特征，有任何借阅历史则整批拒绝；已有副本或已归档的来源书目会跳过，不无限增加馆藏。
- `catalog:covers` 先通过 psql 导出当前数据库中全部番茄来源 ID，再从官方公开书库匹配图片地址，按全局每两秒最多一次请求下载；只接受官方图片 CDN 的 HTTPS 地址，401/403/429 时停止。数据库导出沿用标准 PGHOST/PGPORT/PGUSER/PGDATABASE 配置，默认本机开发库；应用文件关联仍使用 Java 的 DATABASE_URL/USER/PASSWORD 配置。不要把两套连接配置指向不同数据库。
- 官方目录对大分页可能返回少于请求数量的条目，封面采集固定使用每页 10 条，避免 offset 产生遗漏。仅匹配来源 ID；不依赖字体编码的书名。书目页和公开搜索在本次仍有空响应，未用于绕过访问限制，要求登录的接口没有继续使用。
- 图片校验 JPEG/PNG/WebP 完整头尾或长度，最多 5 MB，先写临时文件再原子改名。结果清单 `data/fanqie-covers.json` 保存文件名、SHA-256、字节数、原始 coverUri 和时间，缺少 ID 单独记录。临时签名图片地址只在下载期间使用，不保存到源码或数据库。
- 文件默认位于 `~/Library/Application Support/library-system/covers`。Java 关联工具再次核对文件长度和 SHA-256，整批事务更新 books 和来源元信息。图书目录与详情显示本地封面，缺少或加载失败时显示原首字占位；封面接口需要登录，归档权限沿用书目查询。
- `LIBRARY_COVER_DIR` 可改变文件目录，下载与 API 必须使用同一个值。迁移项目时数据库和封面目录需要一起复制；pg_dump 不包含图片，Compose 示例给封面配置独立持久化卷。

需要恢复虚构示例时可以显式运行 `db:seed`，这会重新生成四本演示书和各三册副本，使用新 UUID 与继续递增的馆藏编号，保留番茄数据。需要精确恢复旧 UUID 时，先把整理前备份恢复到独立测试库核对再设计数据恢复步骤，不直接覆盖已经有新操作的开发库。
